# Grill me

The user has an idea for CampusHub: read it in the arguments. Before any planning or code:

1. Read the code areas the idea touches, so your questions are grounded in reality.
2. Ask **one question at a time**, starting with the one whose answer would change the
   design most. Explain in one sentence why it matters. Wait for the answer.
3. Keep going until you can state: the goal, who it is for, the exact behaviour
   (including edge cases), what is out of scope, and how we will know it works.
4. Then write a one-page summary of the agreed requirements and ask the user to confirm it.

Do not propose solutions or write code during the interview.
